# 「3 実行設定」

NWChemとMPIの起動条件を設定し、ジョブとして保存します。上部に対象の計算（手法・基底・計算目的の1行）、「終了したら結果ビューアに読み込む」「ジョブとして保存」、左に設定（実行先・実行ファイル・保存先、計算資源、追加の環境変数）、右に「実行前の確認」「起動コマンド」を並べます。計算はヘッダーの「計算を実行」（F5）で開始し、ヘッダーの「停止」で止めます（このタブに同じボタンは置きません）。実行中・最後の計算の状態とログは、どのタブでも開ける実行パネル（下記）に表示します。実行ファイルは名前（PATHから検索）またはパスで指定し、名前で指定したときはPATHで見つかった場所を欄の下に表示します（パスで指定したときは右の確認欄だけ。見つからないときは理由を欄の下にも表示）。プロジェクトを開いただけでは実行しません。

- **実行パネル（実行状況とログ）**: ウィンドウの下部、タブの下に開き、開いている間はタブがその分だけ低くなります（重ねないのでタブの内容を隠さず、タブの幅も変わりません）。計算を始めると開きます。ヘッダーの「実行中」、ステータスバーの実行状況、「計算 → 実行状況とログ」（Ctrl+Shift+L）、「履歴」の「実行状況とログを表示」、このタブの「実行状況とログを表示」からどのタブでも開け、ヘッダー・ステータスバー・メニューからは閉じることもできます。閉じても計算は続きます。
  - **高さ**: タブとの境目をドラッグして変えられ、アプリ設定に記憶します。パネル右上のボタンでタブの場所まで広げられ、タブを開くと元の高さに戻ります。タブとパネルを並べられない低いウィンドウ（高さ約710 px未満）では最初からタブの場所に広げ、タブを開くとパネルを閉じます。結果ビューアの表は、低くなって選択中の行が隠れるときは行が見える位置へスクロールします（スクロールして行を画面の外にしていたときは動かしません）。
  - **実行状況（左の欄）**: 見出しの行に保存・実行したジョブの状態（実行中・終了・停止・失敗・保存のみ）と経過時間（実行中は開始時刻も）を表示します。欄にはジョブフォルダーとそれを開くボタン、「結果ビューアへ」「履歴で見る」、実行中は「停止…」（ヘッダーの「停止」と同じく確認してから停止）を表示します。実行中は入力の `task` ごとに（構造最適化・振動数など）完了・実行中・待機を示し、最適化中はログの「@」行から最新のステップ・エネルギー・ΔE と、Gmax・Grms・Xrms・Xmaxの値をNWChemの閾値と比べて達成・未達を表示します（変位は最初のステップでは判定しません）。taskが多くて収まらないときは欄がスクロールします（ボタンは隠れません）。
  - **ログ（右の欄）**: 標準出力・標準エラーを表示します。ログは実行中のものを読むだけで、ファイルは変更しません。
  - **終わったとき**: 正常終了すると「結果ビューアへ」を青いボタンにします。パネルを開いたまま結果ビューアを開くと（結果ビューアを表示中なら終了後の読み込みが済むと）パネルは閉じます。閉じた後に開き直したパネルは自動では閉じません。失敗したときは、閉じていてもパネルを開き、標準エラーに出力があれば標準エラーを表示します（次の実行では標準出力に戻ります）。
- **実行中の編集**: 分子や条件は実行中も編集でき、起動済みの計算には反映しません（このタブにも表示します）。

## 計算キュー

「3 実行設定」の「キューに追加」で、現在の分子・条件を入力一式として保存し、待機列へ登録します。実行中も別の分子・条件を登録できます。「計算キュー」で一覧を開き、「キューを開始・再開」で1件ずつ実行します。待機中の計算は上下への並べ替えと「登録を取消」ができ、各行に保存先・状態・開始できなかった理由を表示します。

「キューを一時停止」は次の計算から有効で、実行中の計算は続きます。「実行中を停止」は現在の計算を停止します。「失敗・停止・時間切れでキューを一時停止」は既定でオンです。終了コード0でも、標準出力・標準エラーの末尾128 KiBに認識できるSCF未収束・最適化上限・メモリ・基底のエラーがあれば停止します。診断がないことは収束の保証ではありません。

登録後の編集は登録済みの計算へ反映しません。開始時に保存済みの入力・プロジェクト・実行記録と実行条件を再検査し、変更や出力先の衝突があれば拒否します。外部の入力movecsや実行ファイル自体のコピーは作りません。履歴には登録時から「保存のみ」として現れ、開始後は通常の実行状態になります。登録の取消は入力一式を削除しません。

キューは1000件までです。待機中の計算と順番、失敗時の方針は、MolFormaのデータフォルダーの `queue.json` に記録し、次の起動時に復元します。復元したキューは一時停止の状態で、「キューを開始・再開」を押すまで開始しません。登録時から実行記録（`run.json`）が変わったジョブは復元しません。同じアカウントで2つ目のウィンドウを開いた場合、そのウィンドウのキューは従来どおりセッション内だけのものです。`--mcp-gui` で起動したセッションはキューを復元しません。同時実行には対応しません。

### 複数の計算を順に実行する

1. 分子と「2 計算条件」を整え、「3 実行設定」の実行前の確認を通して「キューに追加」を押します。
2. 次の分子・条件へ変更し、同じ操作で登録します。登録済みの計算は、その後の編集では変わりません。
3. 「計算キュー」で待機行を選び、必要なら「上へ」「下へ」で順番を変更します。「失敗・停止・時間切れでキューを一時停止」の方針を確認し、「キューを開始・再開」を押します。
4. 失敗で止まった場合は、実行パネルの診断とログを確認します。条件を直して新しいジョブを登録し、残りを続ける場合はキューを再開します。

### 前の計算から続けて登録する（反応経路の連鎖）

「計算キュー」の「前の計算から続けて登録…」で、キューの計算が正常に終わったときに、その構造から次の計算を始めるように登録できます。スキャンやNEBの最高点から遷移状態探索、IRC、IRCの両端の最適化までを、計算の終わりを待たずにまとめて登録する使い方です。

1. 最初の計算（座標スキャン・NEB・遷移状態探索など）を「キューに追加」で登録します。
2. 「計算キュー」の「前の計算から続けて登録…」を押し、「引継ぎ元」でその計算を、「引き継ぐ構造」で「最終構造」「経路のエネルギー最高点」（座標スキャン・IRC・NEBの点。NEBの両端は除く）「IRCの前進側の端」「IRCの後退側の端」のどれかを選びます。引継ぎ元がスキャン・IRC・NEBのときは最高点、それ以外は最終構造を初めに選びます。
3. 登録する計算を選びます。「「2 計算条件」の今の条件で1件」は今の条件をそのまま1件、「反応経路の連鎖」は「遷移状態探索 → 振動数」（計算名に `_ts`）、「IRC（両方向）」（`_irc`）、「IRCの両端の構造最適化」（前進側 `_fwd`・後退側 `_bwd`、既定で振動数も）のうち選んだものを、この順に前の段階の構造から続けて登録します。連鎖の各段階は今の手法・基底などを使い、計算目的と計算名だけを変えます。
4. 「キューに登録」を押し、「キューを開始・再開」で実行します。

連鎖で登録した計算は、引継ぎ元が正常に終わった時点で、そのジョブの `output.out` から構造を読み取り、原子の座標を置き換えてから入力一式を保存して実行します（登録時には入力一式を作らず、一覧の「保存先」は「（前の計算の終了後に保存）」です）。登録時には条件と原子の数・順番を検査し、連鎖の途中の段階でエラーになる組合せ（3原子未満のIRCなど）は1件も登録しません。引継ぎ元より前へは並べ替えられません。引継ぎ元が失敗・停止・取消になった計算は開始せず「失敗」になり、引継ぎ元の登録を取り消すと、そこから続く待機中の計算も取り消します。待機中の連鎖はキューと一緒に `queue.json` に保存し（入力一式がまだないため分子・条件もそこに保存します）、次の起動時に復元します。NEBが最大ステップ数で止まっても正常終了として扱い、最高点から続けます。構造は原子の順番で対応させ、固定原子が動いた結果は拒否します。分子軌道やHessianは引き継ぎません（それには「履歴」の「この結果から次の計算」を使います）。

## ウィンドウを閉じても計算を続ける

計算は、MolFormaが起動する見張り用のプロセス（同じ実行ファイルの `--run-job` モード）がNWChemを起動して管理します。このプロセスはウィンドウとは別に動くため、MolFormaを閉じても、MolFormaが異常終了しても、計算は続きます。状態・終了コード・制限時間・診断は、このプロセスが `run.json` に記録します。

- **閉じるとき**: 実行中の計算があると「計算を続けて閉じる」「計算を停止して閉じる」「キャンセル」から選びます。続けた場合、待機中のキューは保存され、実行中の計算が終わっても次の計算は自動では始まりません。
- **次に起動したとき**: 前回から続いている計算を見つけると監視を再開し、ヘッダー・実行パネル・「履歴」に実行中として表示します（ステータスバーに知らせます）。停止もできます。すでに終わっていた場合は、その状態をステータスバーに表示します。
- **別のウィンドウの計算**: 「履歴」で実行中のジョブを選ぶと、ほかのウィンドウや前回の起動で始めた計算も「この計算を停止」で止められます（確認あり）。停止は、ジョブフォルダーに `stop.request` を置いて見張り用のプロセスに依頼します。
- **見張り用のプロセスが失われたとき**: NWChemが動いていれば「実行中」のまま表示し、停止するとNWChemのプロセスを直接終了します。NWChemも終了していれば「中断・プロセスなし」になり、「記録を修復」で直せます。

見張り用のプロセスは、MolFormaが保存した直後のジョブ（状態が「起動中」で、入力のSHA-256が記録と一致するもの）だけを実行します。終了したジョブのフォルダーを指定しても何も起動しません。PCの再起動やログアウトで計算が終了するかどうかはOSの設定によります。AppImageではAppImage自身を見張り用のプロセスとして起動します。

## 別の計算機で実行する（ジョブスクリプト）

MolFormaからSSHで転送・投入するときは[リモートの計算機で実行する](#リモートの計算機で実行するsshslurmpbs)を使います。SSHで接続できない計算機には、「ジョブとして保存」のフォルダーへ起動用のスクリプト `job.sh` を加えて手で複写し、戻ってきた出力を「履歴」で登録できます。

1. 「3 実行設定」の「ジョブスクリプト」で「シェルスクリプト」「Slurm（sbatch）」「PBS（qsub）」のどれかを選びます。SlurmとPBSではキュー・パーティション名も指定できます（任意）。
2. 「ジョブとして保存」でジョブフォルダーを作ります。`job.sh` には、起動数・スレッド数・制限時間（指定時）と、「3 実行設定」の実行ファイル・MPIランチャーの名前をそのまま書きます。
3. フォルダーごと実行先へ複写し、`sbatch job.sh`（Slurm）、`qsub job.sh`（PBS）または `./job.sh` で実行します。出力は同じフォルダーの `output.out` と `stderr.err` で、NWChem（MPIランチャー）の終了コードを `exit_code` に書きます。
4. `output.out`（と必要なら軌道などのファイル）を元のジョブフォルダーへ戻し、「履歴」でそのジョブを選んで「外部で実行した結果を登録」を押します（[「履歴」](history.md#外部で実行した計算を取り込む)）。

| 種類 | スクリプトの先頭（既定のテンプレート） | 作業先 |
| --- | --- | --- |
| シェルスクリプト | なし | スクリプトのあるフォルダー |
| Slurm | `#SBATCH --job-name`・`--nodes=1`・`--ntasks`（MPI起動数）・`--cpus-per-task`（スレッド数）・`--time`・`--partition`・`--output=scheduler-%j.log` | `SLURM_SUBMIT_DIR` |
| PBS | `#PBS -N`・`-l select=1:ncpus=…:mpiprocs=…:ompthreads=…`・`-l walltime`・`-q`・`-j oe` | `PBS_O_WORKDIR` |

- モジュールの読込みなど、NWChemの前に実行する行は「編集 → 環境設定」の「ジョブスクリプト（別の計算機で実行）」に書きます。この行はプロジェクトには保存せず、このPCで作るすべての `job.sh` に加えます（受け取ったプロジェクトの内容がスクリプトにそのまま入ることはありません）。
- スレッド数の環境変数（`OMP_NUM_THREADS` など）は `export` します。「追加の環境変数」の行はこのPCの場所を指すことが多いため、コメント（`# export …`）として書きます。必要なものは実行先に合わせて有効にしてください。
- 既定の見出しは1ノードでの実行を前提にしています。アカウント名・メモリ・複数ノード・GPUなどは、下記のテンプレートに加えます（その計算機だけに必要な行は、リモート実行先の「見出しの追加行」に書けます）。入力movecsなどの絶対パスは、このPCのパスのまま入力に書かれます。
- ローカルで実行するジョブ（「計算を実行」・キュー）には `job.sh` を作りません。

### スクリプトの見出し（テンプレート）

SlurmとPBSのスクリプトの先頭（`#SBATCH`・`#PBS` の行）は、「編集 → 環境設定」の「Slurmの見出し」「PBSの見出し」に書いたテンプレートから作ります。テンプレートはアプリ設定に保存し、「ジョブとして保存」の `job.sh` とリモート実行の両方に使います。「見出しを既定に戻す」で上の表の内容に戻せます。

| プレースホルダー | 値 |
| --- | --- |
| `{name}` | 計算名（「2 計算条件」の `start`） |
| `{ranks}` | MPI起動数（直接実行では1） |
| `{threads}` | 1プロセスあたりのスレッド数（OpenMPとBLASの大きいほう） |
| `{omp_threads}`・`{blas_threads}` | OpenMP・BLASのスレッド数 |
| `{cpus}` | 起動数 × スレッド数 |
| `{time}` | 制限時間（`HH:MM:SS`）。制限なしのときは値なし |
| `{queue}` | キュー・パーティション名。空欄のときは値なし |
| `{memory_mb}` | NWChemの `memory`（1プロセスあたりのMB） |

- 行は `#` で始めます。値のないプレースホルダーを含む行は書きません（例: 制限時間なしでは `#SBATCH --time={time}` の行を省きます）。
- 未知のプレースホルダー、`#` で始まらない行、制御文字を含むテンプレートは保存できません。

## リモートの計算機で実行する（SSH・Slurm・PBS）

「3 実行設定」の「実行先」で、SSHで接続できる計算機（リモート実行先）を選ぶと、「計算を実行」・キューの計算をその計算機で実行します。入力一式はこのPCのジョブフォルダーに保存し、`ssh`・`scp` で実行先へ複写して投入し、実行中は状態とログを確かめ、終わると実行先のジョブフォルダーをこのPCのジョブフォルダーへ回収します。結果ビューア・履歴・再開・計算の連鎖は、ローカルで実行したジョブと同じように使えます。

1. このPCに OpenSSH のクライアント（`ssh`・`scp`）を用意し、パスワードなしで接続できるようにします（鍵を `ssh-agent` に登録するか `~/.ssh/config` で指定）。初めての計算機には、端末で一度 `ssh 接続先` を実行してホスト鍵を確かめて登録します。
2. 「3 実行設定」の「リモート実行先…」（または「編集 → 環境設定」の「リモート実行先…」）で「追加」し、接続先・作業フォルダー・投入方式などを入力します。「接続を確認」で、一度接続して作業フォルダー・スケジューラーのコマンド・NWChemとMPIランチャーを確かめられます。
3. 「実行先」で登録した名前を選びます。「実行前の確認」に実行先と `ssh`・`scp` が並び、「起動コマンド」には複写先・投入コマンドと実行先で使う `job.sh` を表示します。
4. 「計算を実行」（F5）で実行します。実行パネルの「実行状況」に、実行先・ジョブID・スケジューラーでの状態（待機中・実行中など）を表示し、ログ欄に実行先の `output.out` を確認のたびに追記します。

| 項目 | 内容 |
| --- | --- |
| 名前 | 「実行先」に表示する名前。プロジェクトにはこの名前だけを保存します |
| 接続先（ssh） | `ユーザー名@ホスト名`、または `~/.ssh/config` の `Host` 名。英数字と `. _ @ % + -` |
| ポート | 0では `ssh` の設定どおり（既定は22） |
| 作業フォルダー | 実行先でジョブフォルダーを作る場所。既定は `~/molforma-jobs`。`~/` で始めるとホームから。英数字と `. _ / + -` だけ |
| 投入方式 | シェル（ログインした計算機で `job.sh` をバックグラウンドで起動）、Slurm（`sbatch`）、PBS（`qsub`） |
| NWChem実行ファイル・MPIランチャー | 実行先で起動する名前またはパス。空欄では「3 実行設定」の名前 |
| 状態の確認間隔 | 10〜3600秒、既定30秒。確認のたびにSSHで1回接続します |
| 見出しの追加行 | Slurm・PBSの見出し（テンプレート）の後に加える `#` の行（`#SBATCH --account=…` など）。プレースホルダーも使えます |
| 準備の行 | この実行先の `job.sh` で、環境設定の準備の行の後、NWChemの前に実行する行（`module load nwchem` など） |

- **複写するもの**: ジョブフォルダーの `input.nw`・`job.sh` と、再開のときのデータベースなどです。`run.json`・`project.molforma.json`・メモは複写しません。実行先には、ローカルと同じ名前のジョブフォルダー（`作業フォルダー/計算名-日時-ID`）を作ります。
- **投入**: シェルでは `setsid nohup ./job.sh &`（`setsid` がなければ `nohup` だけ）、Slurmでは `sbatch --parsable job.sh`、PBSでは `qsub job.sh` で投入し、プロセスID・ジョブIDを `run.json` に記録します。コマンドはログインシェル（`bash -l`）で実行するので、端末でログインしたときと同じ `PATH` と `module` が使えます。
- **状態の確認**: 確認間隔ごとに、シェルではプロセス、Slurmでは `squeue`（終わった後は `sacct`）、PBSでは `qstat` で状態を調べ、`job.sh` が書く `exit_code` で終わりを判定します。`exit_code` のないまま終わったジョブは、ファイルの共有の遅れを見込んで2回目の確認で終わりとします。
- **回収**: 終わると実行先のジョブフォルダーを丸ごと複写して戻し、`output.out`・`stderr.err`・`exit_code`・軌道や可視化ファイル・データベースなどをローカルのジョブフォルダーに置きます（`input.nw`・`job.sh`・`run.json`・プロジェクトは置き換えません）。実行先のフォルダーは削除しません。
- **終わり方**: `exit_code` が0なら「終了」、0以外なら「失敗」です。停止したときは「停止」、Slurmの時間切れ（`sacct` の `TIMEOUT`）は「時間制限」、終了コードの記録なしで終わったジョブは「中断」になります。制限時間は、Slurm・PBSでは見出しの `{time}` としてスケジューラーに任せ、シェルでは見張り用のプロセスが経過時間で停止します。
- **停止**: 「停止」で、Slurmは `scancel`、PBSは `qdel`、シェルはジョブのプロセスグループへの `SIGTERM` で止め、その後も結果を回収します。複写中に停止すると投入しません。
- **接続できないとき**: 状態の確認や回収に失敗しても計算は止めず、確認間隔ごとに接続し直します。実行パネルと「履歴」に理由と失敗が始まった時刻を表示します。複写・投入の前の失敗（3回まで再試行）や、作業フォルダーを作れない・投入コマンドが失敗したときは「失敗」になり、`ssh`・`scancel` などの出力を表示します。
- **ウィンドウを閉じたとき・PCを再起動したとき**: 実行先のジョブは見張り用のプロセスとは無関係に続きます。見張り用のプロセスがログアウトや再起動で終わると、ジョブは「履歴」で「未接続」と表示され、「再接続」で新しい見張り用のプロセスが状態を確かめ直します（終わっていれば結果を回収します）。次の起動時やウィンドウが実行中のジョブを見ているときは自動で再接続します。見張り用のプロセスへのシグナルではジョブを止めません。

注意と制限:

- パスワード・ワンタイムパスワードの入力、未登録のホスト鍵の受け入れには対応しません（`BatchMode=yes` で接続します）。鍵とパスワードはMolFormaに保存しません。
- 「追加の環境変数」は実行先へ `export` しません（`job.sh` にコメントとして書きます）。必要な値は実行先の「準備の行」に書いてください。ファイルから読む初期軌道（入力movecs）は使えません。前のジョブから続けるときは「続きから実行を準備」を使います（データベースを複写します）。`scratch_dir`・`permanent_dir` などの絶対パスは実行先のパスとして書かれ、このPCでは確かめません。
- 回収はジョブフォルダー全体です。NWChemの一時ファイルが作業フォルダーに残る設定では、それも回収します。
- 実行先の作業フォルダーとジョブフォルダーのパスには、英数字と `. _ / + -` 以外は使えません（ホームのパスに空白があると失敗します）。
- 実行先の登録は「編集 → 環境設定」と同じアプリ設定に保存し、プロジェクトには実行先の名前だけを保存します。受け取ったプロジェクトの実行先がこのPCに登録されていなければ実行できず、登録されていても、MolFormaで選んでいない実行先なら実行前に確認します。登録を消したり接続先を変えたりした実行先のジョブは、再接続できません。
- MCPからは実行先を変更できません（`set_execution` の `remote` は保護された設定です）。画面なしのMCPサーバー（`--mcp`）でリモート実行するには `--mcp-keep-runs` が必要です。
- 実際のSSHでは、Linuxでシェル（バックグラウンド）の投入を確認しています（下記）。Slurm・PBSは試験用のプログラムでだけ確認しており、実際のスケジューラー、WindowsとmacOSでは未確認です。

## 環境とパス

- `OMP_NUM_THREADS`、`OPENBLAS_NUM_THREADS`・`GOTO_NUM_THREADS`・`MKL_NUM_THREADS`・`BLIS_NUM_THREADS`・`VECLIB_MAXIMUM_THREADS` を専用欄から設定します。`OMP_DYNAMIC` と `MKL_DYNAMIC` はFALSEにします。これらと `OMP_STACKSIZE` の重複指定は環境変数表で拒否します。
- `NWCHEM_BASIS_LIBRARY` を表で指定した場合はプロジェクトの場所を基準に絶対パスへ変換し、末尾に `/` を付けます。ほかの値は文字列として渡し、シェル展開・環境変数展開はしません。通常は親環境とNWChemの `.nwchemrc` による基底設定を利用できます。[NWChem Getting Started](https://nwchemgit.github.io/Getting-Started.html)
- 実際の作業ディレクトリは毎回新しいジョブフォルダーです。詳細設定の相対入力movecsだけを参照基準から絶対パスへ解決し、scratch・permanentの相対パスはジョブ内を基準にします。相対出力movecsはpermanentを基準にし、`./`で始めた場合はジョブ直下を基準にします。ジョブ内の出力用サブディレクトリは作成します。`../` でジョブ外へ出る相対出力先は拒否します。外部の保存先を指定するときは絶対パスを使用します。
- 既存の出力movecs・CUBE・MOLDENや、同じ計算名のファイルが残る外部scratch/permanentへの実行は拒否します。外部ディレクトリは事前に用意してください。ジョブの入力・ログ・実行記録と同じ名前の出力movecsも拒否します。
- 起動には `QProcess` のプログラム名・引数配列を使い、シェルは起動しません。コマンド欄は確認用のPOSIXシェル表記です。保存前の日時・IDはプレースホルダーです。
- ネットワーク上の場所（`\\server\share` や `//server/share`）は、実行ファイル・ランチャー・ジョブ保存先・参照ファイルの基準・環境変数・詳細設定のパスのどれであっても、「編集 → 環境設定」で指定した値でなければ使えず、確認のためにアクセスすることもしません。Windowsでは、ネットワーク上の場所を調べるだけでそのサーバーに利用者の資格情報が送られるためです。

## 保存・実行・停止

NWChem実行ファイル・MPIランチャー・追加の環境変数と、「2 計算条件」の追加入力は、任意のプログラムを起動できる設定です。これらが「編集 → 環境設定」の値とも、この画面で入力した値・実行前に確認した値とも異なる場合（プロジェクト・履歴・自動保存から読み込んだ場合や、MCPで変更された場合）は、「計算を実行」を押すと設定内容を示す確認ダイアログを表示します。相対パスや名前で指定した実行ファイルは、実際に起動する場所も示します。追加入力の全文は「詳細を表示」で確認できます。「はい」を選んだ値は、MolFormaを終了するまで確認済みとして扱います。受け取ったプロジェクトは、内容を確かめてから実行してください。

「ジョブとして保存」（入力一式の保存）はNWChemがインストールされていなくても使えます。実行ファイルや参照movecsをコピーする機能ではありません。別環境で実行する場合はパス・MPI・基底ライブラリをその環境に合わせて用意してください。

「計算を実行」は起動前に同じ入力一式を保存し、次のファイルを作成します。

| ファイル | 内容 |
| --- | --- |
| `input.nw` | 実行する完成したNWChem入力。入力movecsの相対パスを解決済み |
| `project.molforma.json` | 起動時の分子・計算条件・詳細設定・実行設定を含むプロジェクトのコピー |
| `run.json` | 実行ファイル、引数、上書き環境変数、作業先、入力のSHA-256、時刻、状態、終了コード。親環境全体は記録しない |
| `output.out` / `stderr.err` | 標準出力／標準エラーの全文。プロセスから直接保存 |
| `job.sh` | 「ジョブとして保存」で「ジョブスクリプト」を選んだ場合の起動用スクリプト |
| 再開元のファイル | 再開する計算では、再開元のジョブからNWChemのデータベース・分子軌道・Hessian（`計算名.db`・`.movecs`・`.hess` など）を複写 |

計算は非同期で動作します。候補表示中・整形中は実行と入力一式の保存を無効にします。起動後は確定済みのコピーを使い、編集中の分子や設定、別プロジェクトの読込は実行中の計算に影響しません。計算終了時にも分子・座標・既存の結果参照は変更しません。画面では標準出力・標準エラーの末尾128 KiBを表示し、「保存先を開く」で全文にアクセスできます。

停止・制限時間では、見張り用のプロセスがまず終了を要求し、2秒で応答しなければ強制終了します。Unixでは専用のプロセスグループを作り、その子プロセスも停止対象にします。Windowsにはプロセスグループも、コンソールのプログラムが応じる終了要求もないため、2秒後の強制終了で起動したプロセスとその子孫（`cmd.exe`・`wsl.exe`、WSLの `mpirun` とNWChemなど）をまとめて終了します。実行中にウィンドウを閉じる場合は、計算を続けるか停止するかを選びます（[ウィンドウを閉じても計算を続ける](#ウィンドウを閉じても計算を続ける)）。

起動失敗、非ゼロ終了、停止、制限時間を区別して表示・記録します。「終了コード0」はプロセスの正常終了を示します。正常終了したジョブを結果ビューアに読み込むと、ログから読み取った最適化の収束・計算のエネルギー・虚振動の数・励起状態の数を実行パネルの「実行状況」とステータスバーに1行で表示します。各taskの詳細はログを確認してください。

設定は `document.nwchem_execution` に保存し、共有Undo/Redo、Ctrl+S、再読込に対応します。「編集 → 環境設定」（このタブと同じカードと環境変数の表）では、実行先・実行ファイル・起動方式・MPIランチャー・起動数・スレッド数・OpenMPスタック・ジョブ保存先・制限時間・追加の環境変数の既定値と、ジョブスクリプトの準備の行・Slurm／PBSの見出し、リモート実行先、「外部プログラム」の「xTB実行ファイル」（「ツール → xTBで構造を最適化…」で起動するxtb。名前またはパス、空欄ではPATHのxtb）、起動時に水分子を読み込むか（既定はオフで、新規の状態で起動します）、3D描画の方式と表示言語（どちらも再起動後に反映）をアプリ設定に保存できます。既定値は新規作成と、プロジェクト以外の構造ファイル（XYZ・SDF・PDB等）を開いたときに使い、プロジェクトに保存された設定は変更しません。「現在の実行設定を読み込む」で表示中のプロジェクトの値を取り込めます。環境変数表の入力途中もCtrl+Sで確定します。未知のフィールドは保持します。計算プリセットを適用しても実行設定は変更しません。

現在は1ウィンドウにつき同時に1計算です。任意のMPI追加引数は未対応です。終わらなかった計算は「履歴」または実行パネルの「続きから実行を準備」で、NWChemのデータベースから続けられます（[計算の再開と引き継ぎ](history.md#計算の再開と引き継ぎ)）。最適化後の構造は「結果ビューア」の「分子へ候補として適用」で取り込めます。MPI-PRのビルド構成や基底ライブラリの内容までは自動検出しません。

計算はどのタブからでもヘッダーの「計算を実行」や「計算 → 計算を実行」（F5）で開始できます（開始できない状態では「3 実行設定」を開き、理由を確認欄に表示します）。「計算」メニューには停止・ジョブとして保存・結果ファイルを開く・履歴もあります。計算が終わると（終了・失敗・停止・制限時間）、ステータスバー右の実行状況に結果を表示し（結果ビューアに読み込んだログの要約は左にも表示）、MolFormaが背面にある場合はタスクバーで知らせ、デスクトップ通知に対応する環境では通知を出します。「終了したら結果ビューアに読み込む」（既定でオン、アプリ設定に保存）を有効にすると、正常終了したジョブフォルダーを結果ビューアに読み込みます。タブは切り替えません。実行パネルのログ欄は、ファイルに増えた分だけを追記するため、選択した文字列は解除されません（表示は末尾128 Ki文字まで）。「追尾」（既定でオン）または末尾までスクロールしている間は新しい行を表示します。ログの切替（標準出力・標準エラー）・ファイル名・追尾・コピーは「履歴」のファイル欄と同じものです。実行中・最後の計算の状態と経過時間はウィンドウ下のステータスバーに常に表示し、クリックで実行パネルを開閉します。実行中はヘッダーにも経過時間と「停止」を表示します。「停止」はどこから押しても確認してから停止します。

## 失敗原因の案内

実行パネルにSCF未収束、最適化の反復上限、メモリ不足、基底ファイルの読込失敗、制限時間、起動失敗の案内と根拠となるログの行を表示します。失敗・停止・時間切れで終わり、NWChemのデータベースが残っている計算には「続きから実行を準備」を表示します。「診断に関係する設定を開く」で対応する設定へ移動します。診断は`run.json`へ保存し、履歴・MCPでも参照できます。標準出力・標準エラーの末尾128 KiBの既知メッセージを分類するため、すべての失敗を検出するものではありません。計算条件は自動変更しません。再計算は[結果の構造から準備](results.md#結果の構造から再計算を準備)できます。

## 実行設定の検証

`execution`のQt TestはC++製の試験用プロセスで、引数・環境・作業先、入力の固定コピー、パス・既存ファイルの保護、保存互換性、起動失敗、非ゼロ終了、停止・制限時間・Unix子プロセスの終了、ログ量の制限、Undo/Redo、候補、編集中のCtrl+S、終了処理、実行前の確認の各項目、実行中のログから読む進み具合（taskの段階・DRIVERのステップと収束条件）、実行パネルの開閉・配置（タブを隠さないこと、高さの記憶、全面表示、低いウィンドウ）、結果ビューアを開いたときに閉じること、失敗時の標準エラーの表示、「停止…」とヘッダーの表示、実行ファイルの欄の下の表示（PATHで見つけた名前だけ）を検査します。通常のCTestはNWChem・MPI・ネットワークを必要としません。見張り用のプロセスを通した実行・停止・制限時間、ウィンドウを閉じた後の継続と再接続、見張り用のプロセスを失った計算の扱い、キューの保存と復元、ジョブスクリプトの内容とテンプレート、再開の入力と複写するファイルも検査します。リモート実行は、`ssh`・`scp` の代わりにこのPCの別のフォルダーを実行先のホームとして扱う試験用プログラム（`tests/fake_ssh.cpp`）と、`sbatch`・`squeue`・`scancel`・`sacct` の代わりのシェルスクリプトで、シェル・Slurmでの複写・投入・確認・回収、失敗の終了コード、停止、作業フォルダーを作れないとき、接続できない間の再試行、見張り用のプロセスを失った後の再接続を検査します（Unixのみ）。

2026-11-10にLinuxで、NWChem 7.3.1（MPI 2プロセス）のHCNのHF/STO-3G「最適化 → 振動数」を反復上限2で止め、「続きから実行を準備」から再開した計算が、止まった構造のエネルギー（−91.57693978 Eh）から始まって収束し、振動数まで完了することを確認しました。ウィンドウを閉じた後の継続は試験用プロセスで確認しています。AppImage（1.1.0、Arch Linux）でも、MCPのセッションを終えた後に計算が続き、次のセッションから追跡・停止できることを確認しました。WindowsとmacOSでは未確認です。
